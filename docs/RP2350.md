# RP2350 RISC-V setup

The supplied 0.3.1 firmware uses Waveshare RP2350-PiZero, its native RP2350B variant, RISC-V, 150 MHz, Small (-Os), no PSRAM/internal filesystem and Pico SDK USB. The onboard SD slot uses SPI1 while the external LCD stays on SPI0. See [PIZERO.md](PIZERO.md) for wiring and upload steps. Firmware reserves the same first-4-MB layout inside the physical 16 MB flash.

`scripts/install_board.py` adds RPGame PiZero and Pico 2 aliases with RISC-V as their only architecture choice; re-run it after updating the core. `build.py` defaults to `--board pizero`. `--board pico2` retains the 4 MB Pico 2 external shared-SPI SD source profile; it is not prebuilt in this archive.

The core's package/architecture namespace remains `rp2040` for both RP2040 and RP2350. RPGame 0.3 deliberately rejects RP2040 and RP2350 ARM when compiling its storage backend. RPGame 0.2 is the earlier source baseline for those targets.

The runtime transport uses RP SPI, DMA and shared IRQ APIs. The audio sequencer uses PWM and a Pico SDK repeating timer; the LCD, button and piezo GPIOs retain the earlier RPGame mapping. Games use one CPU core. Selecting RISC-V does not make CH32 peripheral registers, IRQ handlers, flash commands or boot files compatible; those layers have been replaced.

The menu and its package images use different linker origins. Use `scripts/build.py`, which bounds each region and generates relocated ROM image metadata. Renaming or wrapping a CHGame binary, standalone RP UF2 or ARM image cannot produce a menu package.

Physical board validation is pending. Test HardwareCheck, then a standalone game, before testing the SD launcher, reset-return path and flash-save persistence.
