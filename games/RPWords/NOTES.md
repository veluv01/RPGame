Agent-facing notes for continuing work here; rules and controls are in README.md (its format: docs/game-readme.md), the platform in the repo-root CLAUDE.md and docs/.

## Snapshot

- Imported from https://github.com/bateske/CHWords at commit af15e9a (2026-10-01); develop here now, not in the old repo.
- Release build (FQBN `CHGame:ch32v:rev0:opt=oslto,rtlib=nano,periph=game,usb=uploadonly`, board package 0.3.0, 2026-10-02): flash sections 50,052 of 50,944 B; the image (check_size's `image:` line, what the save code measures) is 50,404 B, 28 B under the 50,432 B line that keeps both save pages; static RAM 15,788 of 18,416 B (2,628 spare; 8 KB of it is the framebuffer).
- Built-in dictionary: 14,160 words (4,535 entries) in 10,885 B (src/dict/DictData.*, generated by `tools/dict/build_dict.py --bytes 10898`). WORDS.DIC (ENABLE, 168,551 words) is tracked in sdcard/.
- Verification: `chgame check` (host tests: every built-in word both ways, ~200,000 near misses and the rest of ENABLE, the rules against a second implementation, 600 CPU-vs-CPU games checked play by play; every script twice with identical frames, card*.txt with sdcard/WORDS.DIC in the simulator's slot; release build) passed as of 2026-10-01; not re-run since the import.
- Nothing has run on hardware: SD card bring-up (CHSd has never run on a board in any game), the CPU's thinking time, render times, saving across a power cycle.

## Design decisions

- Chosen (owner): the top priority is the largest possible dictionary; animation and features come second but must stay on brand with the casino series. Every flash byte saved elsewhere goes to the built-in word list.
- Chosen (owner): name CHWords, title "WORDS". The trademarked name of the board game it follows must not appear anywhere in the repo (code, docs, notes, commit messages), the same policy as CHBoardwalk's.
- Chosen (owner): hybrid dictionary: a compressed core list in flash (plays with no card) plus the full ENABLE list (2-15 letters) as WORDS.DIC on the SD card.
- Chosen (owner): modes vs CPU (TOURIST / REGULAR / HIGH ROLLER) and 2-player pass-and-play.
- Chosen (owner, visual pass, because the first board looked flat, like a carpet): sizzle over word count that time (the camera, raised tiles and serif letters cost ~3 KB, about 4,000 words). The camera whips between the whole board (8 px squares) and close-up (16 px): close-up while playing; whole board while the CPU thinks, while B is held and at game over.
- Chosen (visual pass): raised ivory tiles with WOOD thickness; premium squares as dark inlays (DL/TL blue, DW/TW red), labelled close up, "2"/"3" from far off; plain squares just dimples ("less is more"); the last play in GOLD. Inspired by CHMahjong's tiles and CHCrossword's zoom.
- Chosen (owner asked): tentative tiles in the chess set's dark-piece tones (SILVER face, BLUE bevel and letter shadow, NAVY edge), lifted off the board; tile letters in CHCrossword's anti-aliased serif (DejaVu Serif Bold, one half-ink tone), 1 px left of centre with a drop shadow; M and W from DejaVu Serif Condensed Bold so every glyph is <= 11 px. Options rows use the serif too; a random word off the card dances as a rainbow banner.
- Rejected: a DAWG (measured 2.7 B/word against ~0.75 for the flash list; `tools/dict/measure.py`). Consequence: the CPU reads the whole flash list (twice) each turn in slices (Ai.cpp) instead of walking a graph.
- Chosen without the owner's review (may be changed): unlimited hints (SELECT lays out the best built-in-list play); no penalty for an invalid word; obvious slurs left out of the flash list only (tools/dict/blocked.txt; the card keeps ENABLE as published); two players with no card get "ALLOW IT ANYWAY?"; the glove appears only over the rack.

## Gotchas

- The loop after any code change: `chgame build`, read check_size's image size, give the headroom to the dictionary (`build_dict.py --bytes N`), rebuild. Nothing fails when the image passes 50,432 B: watch "save pages free: N".
- The built-in list: front coding, Huffman tables chosen by the previous letter, and 24 suffix rules that fold inflections into base words ("closure", roughly doubling words per byte). Encoder `tools/dict/build_dict.py`, decoder `FlashDict.cpp`; `src/dict/DictData.*` are generated, never hand-edit.
- `tools/dict/wordlist.py` downloads ENABLE and Norvig's word frequencies into tools/dict/data/ (gitignored) on first use: network needed once. Until then `chgame test` still passes but prints "0 ENABLE words checked" (it skips the full-list check): run wordlist.py once in a fresh clone.
- `tools/dict/build_sd.py` writes sdcard/WORDS.DIC (a hash table of 512 B blocks: one block read per lookup, no index in RAM). chgame check builds it if missing.
- CPU thinking: on the board `think()` in Screens.cpp runs `ai::step(24)` until 12 ms have passed each tick (the frame rate sags while it thinks); 12 ms is a guess awaiting device numbers. The simulator's clock does not run while code computes, so there it does a fixed `ai::step(1500)` a tick: frames are deterministic in the sim, but think pacing on the device will differ.
- SD: CHSd is used as a library (`#include <Fat.h>`, `<SdSpi.h>`; `../../../../CHSd`); the game holds no copy of it. `chgame build` passes it with `--library`, and the simulator builds `CHSd/src/Fat.cpp` with the pretend card in CHSd's `host/` folder (`$CHSD_CARD`). After changing CHSd run its tests (`python platform/board/arduino/CHGame/libraries/CHSd/tests/run_tests.py`) and this game's `chgame check`.
- SPI1 is shared with the LCD: SD calls only after `gfx_wait()` and before the next flush (the driver hands SPI1 back as CHGfx left it).
- Simulator card: `CHSD_CARD=<file>`. A `*.img` is served as raw card blocks; any other file is put on a pretend FAT16 card (VCard), so the FAT code runs. Sim-only hooks: `X 0|1` pulls/inserts the card, `A` plays for the human.
- Other debug hooks (list above `debugHook` in Screens.cpp): `G mode level seed`, `R letters` (rack), `W row col H|V word`, `H` state, `J T|S|O`.
- Tile letters: `tools/tilefont.py` needs DejaVu Serif Bold and Serif Condensed Bold installed (it searches the usual system font folders) and writes tools/art/tilefont.txt; then `python tools/assets.py`. The glove is CHChess's and the display font's capitals are CHBackgammon's, both shared from the repository's `tools/art/common/` (`hand.png`, `font.txt`).
- Sound: the effects are in Sounds.cpp, played by the CHGame library's engine (chgame/Audio.h); a word lighting up is `audio::note()` in Stage.cpp. Hear them with the shared preview, `chgame audio out/audio`.
- Every game source with code (not the tables-only Sounds.cpp) is built `#pragma GCC optimize("Os", "no-ipa-sra", "no-caller-saves")`: `no-caller-saves` alone took 220 B off the image (2026-10-02). Keep the line the same in every file: a function built with different options is not inlined into one built with others, and a mixed set came out larger.
- The debug protocol is the CHGame library's (`chgame/Debug.h`, on with `CHGAME_DEBUG`; `chgame build --debug` passes `-DCHGAME_DEBUG=1`); the save record's pages and CRC are the library's too (`chgame/Save.cpp`), the game's `Save.*` says what goes in it (one `noinline` call to `save::read()` for both loads: the library's availability test is copied into each caller, 80 B). The script driver is the shared `../../../../../../../../../tools/chsim/chdrivelib.py`; tools/chsim/chdrive.py adds only `auto`, `board`, `waitturn` and `cal`.
- Simulator: `../../../../../../../../../tools/chsim/chsim.py` (shared). Set `CHSIM_CXX` or have zig/clang++/g++ on PATH (see root CLAUDE.md). Size report: `../../../../../../../../../tools/check_size.py`.

## Development

Everything can be checked on a PC (Python 3 with Pillow, and a C++ compiler for the simulator: root CLAUDE.md).

    chgame check               # host tests, every script in the simulator (twice), the device build
    chgame test     # the host tests alone
    chgame sim
    chgame run tools/scripts/ui.txt out/ui    # one script: screenshots in out/ui
    chgame gif    # tools/scripts/gameplay.txt -> docs/gameplay.gif (the README's one GIF, <= 1 MB)
    python tools/dict/build_dict.py --bytes 10898    # rebuild the built-in list to a flash budget
    python tools/dict/build_sd.py       # sdcard/WORDS.DIC, checked word by word
    python tools/assets.py              # the glove, the arrow, the fonts -> src/assets
    chgame upload       # build and upload the release
    chgame size --top 20

- Scripts: `say G 0 2 11` starts a game (mode, level, seed), `say R PLAYERS` sets the rack, `say W 7 3 H WORD` lays a word out; `waitturn`, `auto` and `board` are in tools/chsim/chdrive.py's header, `snap` and `rec` take pictures. gameplay.txt records the README's clips (01_title ... 05_win); showcase.txt and the rest are tests. The same scripts run on the device with a debug build (`chgame run --device SCRIPT OUTDIR`).
- The host tests check every word of the built-in list both ways (found by lookup, given once by the scan), about 200,000 near misses and the rest of ENABLE (not found), the rules against a second implementation, and 600 games between two CPUs in which every play is checked the plain way: legal, scored right, every word it makes in the list, the tiles from the rack, a hundred tiles in all.
- The card for a player: `sdcard/WORDS.DIC` (4 MB) in the top level of a FAT32 or FAT16 card (not exFAT, which cards of 64 GB and more come as), named exactly `WORDS.DIC`. The title says `168551 WORDS ON THE CARD` when it has found it and `14160 WORDS  NO CARD` when not; a card put in later is found the next time the title comes up. Pulled out in mid-game, the game says so and carries on with the built-in list.
- From the Arduino IDE: board CHGame Rev0, *Optimize* Smallest + LTO (the default; it does not fit without), *USB* Upload only (it stops with a message otherwise). The board package (0.3.0 on) brings CHGfx, CHGame and CHSd.
- The CPU's search (Ai.cpp): pass one finds, for every empty square beside a tile, which letters would make a word with the tiles across it; pass two tries every word everywhere it could go (a word needing letters the rack has not got must run through them on the board, which leaves few places). It only ever plays built-in words, so never one the card would refuse; the hint is the same search.
- The bag is shuffled by one generator, seeded from the moment the button is pressed, that the CPU's code does not look into.
- Drawing: the tiles are rounded rectangles in two colours (the face and its thickness) and a letter: the serif close up and in the rack (546 B for all 26), the 3x5 font far off. The close-up shows eight columns and six rows, the camera following the cursor and keeping the first tile of the word being laid in view. The only stored art is the glove, the arrow for the way a word runs and the display font.
